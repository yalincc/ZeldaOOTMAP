## 1. 项目概览

`onif.info/ocarina` 是一个针对现代平台（Nintendo Switch 2 版）《塞尔达传说：时之笛》制作的 Web 端在线存档查看与修改工具。

### 核心亮点
1. **纯 Web 沉浸式交互**：无需安装客户端，直接在浏览器中拖拽 `slot_XX` 存档文件夹（或 `caption.sav` + `progress.sav`）。
2. **多槽位管理与本地持久化**：使用浏览器的 IndexedDB / LocalStorage 缓存用户导入的多个存档槽位草稿，切换不丢失进度。
3. **极高维度的修改覆盖（3,800+ 字段）**：从生命、卢比、全道具、装备、迷宫钥匙，到全游戏 3288+ 项事件/NPC对话 Flags 均可修改。
4. **双向导入导出**：在网页端修改后，由后端/WebAssembly 计算校验码并重新打包生成符合实机/模拟器规范的 `.sav` 文件供下载替换。

## 2. 存档文件规范 (Switch 2 版)

Switch 2 版时之笛的存档目录通常位于每个槽位对应的文件夹中：
```
slot_00/
├── caption.sav    # 槽位元数据（截图/缩略图、游玩时间、保存日期、林克心数/卢比、当前地点等）
└── progress.sav   # 核心游戏进度与全量世界状态数据（背包、剧情标记、世界Flag、装备等）
```

- **文件大小**：
  - `caption.sav`: 约 39 ~ 40 KB
  - `progress.sav`: 约 117 ~ 121 KB
- **二进制头部 Magic**：
  - `0x04 0x03 0x02 0x01`（即小端序 `0x01020304`）
  - 后续跟随时钟/版本头：`EB 80 2D 00 ...`

## 3. Web 架构与接口设计

前端由三个核心静态脚本构成：
1. **`storage.js`**：基于 IndexedDB 的本地存档库管理器，支持草稿分支、变更对比、防丢失保护与离线浏览。
2. **`editor-model.js`**：数据模型驱动层，定义字段分类、批量操作（如全满、全部解锁）、容量上限联动、空瓶内容物绑定等业务规则。
3. **`app.js`**：UI 视图渲染层，支持搜索、分类过滤、虚拟列表滚动、变更差异高亮、导出下载。

### 后端 API 交互（或本地 WASM 封装）
- **`POST /api/demo`**：返回官方演示存档的全量 JSON 树形结构（约 1.45 MB），用于未导入存档时的体验。
- **`POST /api/import`**：接收前端上传的 Base64 编码文件（`progress.sav` 与 `caption.sav`），由后端解析二进制结构并返回带有分类、字段 ID、类型、范围与描述的结构化 JSON。
- **`POST /api/export`**：接收原始文件 Base64、编辑凭证 `edit_token` 以及变更差量字典（`changes: { "f_xxx": value }`），由服务端生成修改后的二进制文件流供前端下载。
- **`GET /api/item-limits`**：获取不同容量升级阶段对应的数量上限规则。

## 5. 对我们当前《时之笛》交互地图项目（`ZeldaOOTMAP`）的启发与复刻价值

我们的项目目前是一个功能齐备的**海拉鲁与地下城全要素攻略地图**，记录了 116+ 核心点位（心之碎片、黄金骷髅蜘蛛、大妖精之泉、魔豆软土、宝箱等）。

结合该存档修改器，我们未来可实现极其惊艳的**杀手级功能**：

### 阶段一：存档自动验票与进度同步（Read-Only Sync）
- **痛点**：目前玩家使用攻略地图时，必须手动逐个点击“标记为已完成”，极为费时。
- **结合方案**：
  1. 在地图界面增加“**拖入 Switch 2 存档同步进度**”入口。
  2. 利用解析库直接提取 `progress.sav` 中的：
     - 已收集的 **心之碎片 / 黄金骷髅蜘蛛** 标志位（在 `history` 与 `quests` 中均有对应 bit）。
     - 各迷宫的 **通关状态、宝箱开启、钥匙获取**。
     - **大妖精泉、魔豆软土种植** 的对话与触发记录。
  3. 瞬间**自动点亮/过滤地图上的所有已完成点位**，玩家立即清楚自己还漏了哪几个心之碎片或哪只蜘蛛！

### 阶段二：内置存档修改器 / 导出（Read-Write Feature）
- 允许玩家在攻略地图页面上直接点选“我要这个道具”、“补齐我的心之碎片”、“修改卢比为 500”、“解锁全曲谱”，然后一键下载重新计算了 Checksum 的 `progress.sav`，真正做到“攻略地图 + 存档修改”一体化。

## 6. 技术自研 / 复刻备忘

1. **校验码与哈希算法**：
   - Switch 2 版保存的数据包含了校验和（CRC32 / Checksum block），需要提取其序列化与反序列化逻辑。
2. **纯前端解析（WebAssembly / TS）方案**：
   - `onif.info` 目前部分通过云端 `/api/import` 处理，但对于单机/离线工具，使用纯客户端 TypeScript 或 Rust-WASM 进行二进制解析与导出体验更佳且无需服务器维护成本。
3. **备份存储目录**：
   - 官方 Demo 数据样本已提取保存在脑图 scratch 目录：`scratch/demo.json`，内含全 3,826 个字段的 ID、分组、类型与说明，可直接作为后续数据字典对照表使用。
