## 2. 为什么用 `master` + `deploy` 两个分支

项目红线规定 **`app/assets` 不入库**（可由 romfs + `tools/` 重建），但线上必须带底图、图标和区域图，否则页面无图。

因此：

- `master`：只存源码、数据、工具、文档；`app/assets` 继续被 `.gitignore` 忽略。
- `deploy`：由 `master` 的 `app/` 加完整 `app/assets/` 生成，仅用于 EdgeOne 构建；资产用 `git add -f` 强制入库。
- EdgeOne 只监听 Gitee 的 `deploy` 分支。**改完源码不推 `deploy`，线上不会更新。**

## 3. 日常更新流程

> 本机 `git` 未加入 PATH，可直接用 `& 'C:\Program Files\Git\cmd\git.exe'`，或把 Git 的 `cmd` 目录加入 PATH。

### 3.1 改源码并验收

```powershell
cd E:\WorkSpace\ZeldaOOTMAP
python tools\verify_all.py
git status
git add -A
git commit -m "feat: ..."
git push origin master
git push gitee master
```

### 3.2 同步到 `deploy` 分支

首次需要建一个独立 worktree（不要和源码共用工作区）：

```powershell
cd E:\WorkSpace\ZeldaOOTMAP
git worktree add E:\WorkSpace\ZeldaOOTMAP-deploy deploy
```

之后每次更新：

```powershell
cd E:\WorkSpace\ZeldaOOTMAP
robocopy .\app E:\WorkSpace\ZeldaOOTMAP-deploy\app /MIR /NFL /NDL /NJH /NJS
cd E:\WorkSpace\ZeldaOOTMAP-deploy
git status
git add -A
git add -f app/assets
git commit -m "build: 同步线上快照（<master短哈希>）"
git push origin deploy
git push gitee deploy
```

> `robocopy /MIR` 会让 deploy 的 `app/` 与源码 `app/` 保持一致；`app/assets` 只在 deploy 里存在，复制后需要 `git add -f`。

### 3.3 等 EdgeOne 自动构建

推送 `deploy` 后，EdgeOne 会自动拉取 Gitee 的 `deploy` 并构建。正常约 30–40 秒。

检查点：

- 状态：成功
- 分支：`deploy`
- 提交：刚推的短哈希
- 输出目录：`app`

### 3.4 线上验收

```powershell
Invoke-WebRequest -Uri 'https://oot.yalin.site/' -Method Head
python tools\verify_all.py
```

人工检查：

- 首屏默认进区域图，底图与图标正常显示。
- 区域图 / 拓扑图 / 全图三档可切换；缩放换层正常。
- 手机 390×844：侧栏抽屉、底部详情卡、双指缩放、全图聚焦正常。
- 抽查 `assets/ui/basemap_2400.webp`、`assets/maps/field/*.webp`、`js/app.js` 均返回 200，无 404。

## 4. 域名与证书

- DNSPod 已添加：
  - `oot` → CNAME `oot.yalin.site.pages.dnsoe6.com`（TTL 600）
  - `edgeonereclaim.oot` → TXT 归属验证（EdgeOne 添加域名时生成，保留）
- EdgeOne 域名管理显示“已生效”后，HTTPS 配置选 **申请免费证书 → 自动验证**。
- 证书首次签发需要几分钟；签发完成前 HTTPS 可能短暂不可用，HTTP 可先访问。
- 证书由 EdgeOne 自动续签，不需要手工上传。

## 5. 回滚

优先在 EdgeOne 控制台“构建部署”历史里选择上一个成功部署，回滚发布。

只有在需要回退源码时，才在 `deploy` 分支回退并重新推送：

```powershell
cd E:\WorkSpace\ZeldaOOTMAP-deploy
git log --oneline
git revert <问题提交>
git push origin deploy
git push gitee deploy
```

## 6. 禁止事项

- 不要把 `app/assets` 提交到 `master`。
- 不要手工修改 EdgeOne 构建产物；所有线上内容必须来自 `deploy` 分支。
- 不要在未跑 `verify_all.py`、未看 PC/手机两档效果前推 `deploy`。
- `commit / push / tag / Release` 仍按项目规则逐次确认；EdgeOne 自动部署不等于“发版”。
