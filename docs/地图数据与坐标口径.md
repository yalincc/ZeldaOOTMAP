## 2. 两套坐标，别混

| 口径 | 字段 | 单位/范围 | 用途 |
|---|---|---|---|
| 游戏世界坐标 | `world: [X, Y, Z]` | 米（Y 为高度） | 与存档/官方数据对齐、排查点位 |
| 底图百分比 | `x, y` | 0~100（已裁边后的 webp 上） | 页面渲染（`left: x%`、`top: y%`） |

**换算（只由脚本算，不手算）**：

```
px = origW/2 + (X - camX) * (1920 / captureHeight)
py = origH/2 + (Z - camZ) * (1920 / captureHeight)
u% = (px * resizedW/origW - crop_x0) / (crop_x1 - crop_x0) * 100
v% = (py * resizedH/origH - crop_y0) / (crop_y1 - crop_y0) * 100
```

- 只取 X/Z（水平面），Y 不参与投影。
- `crop` 来自 `trim_maps.py` 的 PAD=6 裁边框；同区域不同时代/楼层共用同一裁剪框，避免切楼层图跳动。
- 页面用 `object-fit: contain`，所以 pin 必须落在「实际渲染矩形」里，不能直接按卡片宽高算（`getNodeImageRect()`）。

## 4. 新增/修正点位流程

1. 先查 `data/map_projections.json` 是否有该区域；没有则先跑 `compute_map_projections.py`。
2. 改 `tools/extract_romfs_pins.py` 的提取规则（不要手改 `pins_data.js`）。
3. 重跑：`python tools/extract_romfs_pins.py` → 会重写 `pins_data.js`，并回写 `topology_data.js` 的 gateways 与图宽高比。
4. 跑 `python tools/verify_all.py`：数量、断链、引用三项必须全绿。
5. 浏览器实测：`app/index.html`（边缘点位是否落在图内、切楼层/时代是否漂移）。
