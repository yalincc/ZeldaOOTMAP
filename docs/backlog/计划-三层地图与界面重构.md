# 计划：三层地图（全图 / 拓扑 / 区域）与界面重构

> 状态：**P1-P3 已落地（2026-11-24，待验收）**；P4 手机 HUD/图片压缩/全量校验未开始
> 生成：2026-11-24 · 基线：本地 commit `e87db87`（形态 C 区域地图 + 拓扑双模式，未发布）
> 目标：做成 TOTKmap 式全能地图；去掉顶部整条标题栏，左栏 tab 切换「全图 / 拓扑 / 区域」与「全部 / 童年 / 成年」

---

## 1. 先说结论

三层不是三个互不相干的页面，而是**同一套地图的三种比例尺**：

| 层级 | 看什么 | 主要用途 |
|---|---|---|
| **海拉鲁全图** | 官方整张手绘全图 + 区域印章 + 完成度 | 总览、找大方向、看哪个区域还没清 |
| **拓扑图** | 31 个区域卡片 + 33 条真实连通线 | 看「从哪进、从哪出、走哪条近道」 |
| **区域图** | 单张官方区域图 + 密集点位 + 楼层 | 查漏补缺、点开单个收集物 |

**推荐交互：滚轮/双指缩放跨过阈值自动换层，双击直接下钻；左侧 tab 随时直接跳层。**

不推荐只做「三个 tab」，那样只是三个页面；也不推荐一上来做真正的连续地形缩放——三层的底图投影不同，硬把区域图无缝放大到全图会错位。**用「同中心交叉淡入 + 尺度微调」的语义缩放**，看起来连续，实际是三层各自的相机。

## 2. 全图素材与锚点

### 已有素材

- `app/assets/ui/basemap_4608.webp`：**4608×3360，4.5 MB**，原名 `MapTexWorldAll_00`，官方整张海拉鲁手绘图。
- 这张图已在 `maps_config.js` 里登记为 `hyrule / 海拉鲁全境大世界`，但当前网页没用它做全图视图。
- 结论：**全图层直接用这张官方图，不拼 21 张野外图，不 AI 生成地图。**

### 锚点数据

新增 `app/data/world_data.js`（人工维护，不交给 `regions.js` 生成器）：

- 21 个野外区域锚点：`{regionId, x, y, label, era}`，坐标是 `basemap` 的百分比。
- 10 个迷宫入口锚点：`{dungeonId, parentField, x, y}`，挂在所属野外区域附近。
- 全图只显示「区域印章 + 完成度 + 迷宫入口」，**不铺 362 个点位**。原因：
  - 手绘全图不是严格按游戏世界坐标等比绘制，硬投 362 点会出现「点落在错误地标」；
  - 全图铺满 362 点会糊成一片，失去总览意义。
- 后续若要把点位也上全图，先用 5~6 个已知地标做仿射校正，再逐区检查；这是二期，不进本批。

**锚点校准**：设置里保留「高级校准」，支持 `?calibrate=world` 拖动 31 个锚点并导出 `world_data.js`，不开放给普通用户。

## 3. 三层缩放规则（建议值，全部做成配置）

所有百分比都是**相对当前层级自己的适配比例**，不是浏览器窗口缩放，这样 PC/手机一致。

| 从 | 触发 | 到 | 进入尺度 | 锚点 |
|---|---|---|---|---|
| 区域图 | 缩小到 **≤33%** | 拓扑图 | **52%**（聚焦当前区域节点） | 当前区域节点中心 |
| 拓扑图 | 缩小到 **≤17%** | 全图 | **100%**（整图适配） | 视口中心最近的区域锚点 |
| 全图 | 放大到 **≥150%** | 拓扑图 | **100%**（聚焦该区域节点） | 光标/视口中心最近的区域锚点 |
| 拓扑图 | 放大到 **≥200%** | 区域图 | **100%**（区域适配） | 视口中心最近节点（240px 内） |

**为什么进入尺度不统一**：
- 区域 33% 时，地图约 330px 宽；拓扑 52% 时节点卡约 290px，视觉上接近，所以从区域进拓扑用 52%。
- 全图 150% 时已经放大到局部；进拓扑用 100% 聚焦节点，避免节点卡突然缩成一小块。
- 拓扑 200% 时节点卡已接近整屏；进区域用 100% 铺满，完成下钻。

**防误触（必须做）**：
- 只在滚轮/双指手势**结束后 120ms**判定一次，不在手势中途换层。
- 换层后 **500ms 锁定**，避免边界反复横跳。
- 反向阈值天然有死区：区域 33% 出、拓扑 200% 才回区域；拓扑 17% 出、全图 150% 才回拓扑。
- 拓扑放大到 200% 时，若视口中心 240px 内没有节点，**不自动切区域**，只提示「双击区域进入」，避免随机开图。
- `prefers-reduced-motion` 下取消 250ms 过渡，直接切层。

**双击规则（绕过阈值，直接下钻）**：
- 全图双击区域印章 → 该区域图（100%）。
- 拓扑双击节点卡 → 该区域图（100%）。
- 全图单击印章 → 选中并弹出区域小卡（名称、完成度、时代、进入按钮），双击才进。
- 区域图双击空白 → 保持现有「以双击点为中心放大 1.5 倍」，不改。

**过渡表现**：
- 250ms 交叉淡入 + 轻微 scale 补偿；不做白屏、不做左右滑页。
- 换层时保持「鼠标/双指中心」对应的地点不跑出视野。
- 顶部不显示标题栏；图层名和百分比放在右下缩放 HUD（`区域图 · 100%`）。

## 5. 全图层怎么画

- 底图：`basemap_4608.webp`，首次进入全图层才加载；上线前压到 2560 宽（q80）并懒加载。
- 区域印章：金色圆环 + 区域名 + `完成/总数`；完成度用环填充，不只用数字。
- 迷宫入口：小型门形图标，挂所属野外区域旁；缩放 ≥110% 才显示文字，避免重叠。
- 低缩放（100%）只显示印章/环，不显示长标签；标签在 hover/放大后出现。
- 当前选中区域有金色呼吸光；其他区域降透明度。
- 童年/成年：沿用 `isRegionAvailable()`；不可进入的区域印章降为灰色或隐藏，和区域列表口径一致。
- 全图不显示分类筛选；分类在区域/拓扑层继续生效。

## 6. 技术拆分

现在 `app.js` 已约 2000 行，再塞全图和换层会失控。建议本批顺手拆成：

```
app/js/
  app.js            # 启动、把各视图接起来
  core.js           # state、localStorage、时代、分类、进度、URL
  level.js          # 三层阈值、锚点映射、换层锁、过渡
  view-region.js    # 现有区域引擎平移
  view-topology.js  # 现有拓扑引擎平移
  view-world.js     # 新增全图相机 + 印章 + 入口
app/data/
  world_data.js     # 21 野外锚点 + 10 迷宫入口 + basemap 元信息
```

- 先做「行为不变」平移，再改 UI；每步截图对照，避免拓扑/区域回归。
- 共享逻辑（筛选、进度、详情卡、localStorage、URL）留在 `core.js`。
- 三层相机各自独立，但共用 `pan/zoom/pinch` 工具函数。
- URL：`?view=world|topology|region&area=...&floor=...&era=...&pin=...`；旧 `?mode=` 兼容映射到 `view=`。
- localStorage：沿用 `oot_map_done_pins_v3` 等 key，新增 `oot_map_view`。
